# DataProof AI

## Problem
DataProof AI addresses the "Proof-Carrying Data Analyst" challenge (HNX26PSI08). It aims to provide natural language query capabilities over messy, real-world data across multiple tables (CSV/Excel) while ensuring that every numerical answer is backed by verifiable, reproducible code. It strictly avoids AI hallucination by returning intelligent refusals when data is insufficient.

## Solution
The application follows a complete end-to-end pipeline:
Upload → Profile → AI Reasoning → Code Generation → Code Execution → Verification → Evidence

1. **Upload**: Users upload CSV or Excel files.
2. **Profile**: The backend immediately profiles the datasets for structure and data quality (missing values, duplicates).
3. **AI Reasoning**: Gemini 1.5 Pro analyzes the user question against the dataset schemas and determines answerability.
4. **Code Generation**: The AI generates precise Pandas/Python code to compute the answer.
5. **Code Execution**: The backend securely executes the code against the in-memory pandas dataframes.
6. **Verification & Evidence**: The result is verified and presented alongside the exact python code, data sources, and execution time to the user, providing full transparency.

## Architecture
- **Frontend**: React + TypeScript + Vite + Tailwind CSS + Recharts
- **Backend**: Python + FastAPI + Pandas + OpenPyXL
- **AI**: Google Gemini API

## Setup
### Prerequisites
- Node.js (v18+)
- Python 3.10+
- Google Gemini API Key

### Backend Setup
```bash
cd backend
python -m venv venv
source venv/bin/activate
pip install fastapi uvicorn pandas numpy openpyxl google-generativeai python-multipart pydantic-settings
```

### Environment Variables
Set the Gemini API key in your terminal before running the backend:
```bash
export GEMINI_API_KEY="your-api-key-here"
```

### Frontend Setup
```bash
cd frontend
npm install
```

## Running Locally
**1. Start the Backend:**
```bash
cd backend
source venv/bin/activate
export GEMINI_API_KEY="your-api-key-here"
uvicorn main:app --reload
```

**2. Start the Frontend:**
```bash
cd frontend
npm run dev
```

**3. Generate Demo Data (Optional):**
```bash
cd backend
python generate_demo_data.py
```
This generates `sales.csv`, `customers.csv`, and `products.xlsx` in `backend/datasets/` for testing.

## Limitations & Future Work
- **Security**: Current execution of python code relies on simple string filtering. For production, a sandboxed environment (e.g. gVisor, WebAssembly) is required.
- **Scalability**: Datasets are stored in memory (pandas). Future versions could support SQL DBs (e.g., DuckDB) for larger data.
- **Persistence**: Sessions and uploaded data are not persisted across restarts.
